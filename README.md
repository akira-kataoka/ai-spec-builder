# AI指示書ビルダー

AIにシステム開発を依頼するための**指示書**を、フォームと画面設計エディタから作成するツールです。

- 文章で伝えられることは **フォーム** に入力する
- 画面の見た目・配置で伝えたいことは **図形を置くエディタ** で作る
- どちらも最終的に **1本の Markdown** として書き出され、そのままAIに貼り付けられる

依存パッケージなし・ビルド不要。HTMLファイルを開くだけで動きます。

**公開URL: https://akira-kataoka.github.io/ai-spec-builder/**

初めて開いたときは「はじめかた」から、**雛形を選ぶ**か**記入済みのサンプルを読み込む**かを選べます。何ができるツールなのかは、サンプルを読み込んで「出力」を見るのが一番早いです。

---

## なぜ作るか

AIに開発を頼んでうまくいかない原因のほとんどは「AIの能力」ではなく「指示の抜け」です。とくに抜けやすいのが次の4つです。

| 抜けやすいもの | 起きること |
| --- | --- |
| 受け入れ条件 | 「完成」の基準が共有されず、作り直しになる |
| 画面のレイアウト | 文章だけでは伝わらず、想像で作られる |
| やってほしくないこと | 頼んでいない機能が勝手に増える |
| 既存コードの制約 | 既存の書き方を無視した実装が返ってくる |

このツールは、上の4つを含む11のセクションを順に埋めるだけで、抜けのない指示書ができるようにしたものです。

## できること

### 1. フォームで書く（10セクション）

基本情報 / 背景と目的 / 技術と制約 / 機能要件 / 画面設計 / データモデル / API・連携 / 処理フロー / 非機能要件 / 進め方

- 技術スタックはクリックで選ぶだけ（React、FastAPI、PostgreSQL など）
- 機能は1件ずつカードで登録し、**受け入れ条件をチェックリスト形式**で書ける
- 機能に**関連する画面**を紐づけられる（指示書で機能と画面が対応づく）
- 「やってほしくないこと」はよく使う項目をワンクリックで追加できる
- 空欄の項目は指示書に出力されないので、埋まったところだけで成立する

### 2. 画面設計を図で作る

40種類の部品をキャンバスに配置して、ワイヤーフレームを作れます。

- **レイアウト**: グループ枠 / カード / 区切り線 / 余白 / モーダル / セクション
- **ナビゲーション**: ヘッダーバー / サイドメニュー / タブ / パンくず / ページネーション / ドロップダウン
- **入力**: 入力欄 / 長文入力 / セレクト / チェックボックス / ラジオ / トグル / ボタン / 検索 / 日付 / ファイル選択
- **表示**: 見出し / テキスト / ラベル / 画像 / アバター / テーブル / リスト / バッジ / グラフ / 数値サマリ / 進捗バー / アイコン / 通知 / 空状態
- **注釈**: 注釈メモ / 番号付き注釈 / 矢印 / 強調マーカー

ドラッグで配置、ハンドルでリサイズ、8pxグリッドにスナップ。複数画面を作って**画面遷移**も定義できます。

### 3. 図を「構造」として書き出す

ここがこのツールの中心です。配置した部品は、画像だけでなく**入れ子の構造**として出力されます。

```markdown
**レイアウト**（上から下・左から右の順。字下げは「その中に含まれる」ことを表す）

- **1.** ヘッダーバー「備品貸出管理」（上部・全幅）
- **3.** カード「申請内容」（中央中央）
  - **5.** セレクトボックス「備品」 選択肢: ノートPC / プロジェクター (必須) — 一覧で選んだ備品を初期値にする
  - **7.** 日付入力「開始日」 — 過去の日付は選べない
- **11.** ボタン「申請する」(主ボタン)（下部左） — 押すと確認ダイアログを開く

**オーバーレイ（初期状態では表示しない。開く条件は注釈を参照）**

- **4.** モーダルダイアログ「送信確認」（中央右） — 「申請する」を押したときだけ表示する
  - **6.** テキスト「この内容で申請します。よろしいですか。」

**画面遷移**

- 12. ボタン「戻る」 を操作 → 「備品一覧」へ
```

座標の包含関係から入れ子を組み立てるので、**「このボタンはカードの中」「この入力欄はモーダルの中」が伝わります**。モーダルなどの初期非表示の部品は別枠に分け、付箋の注釈は部品に紐づけて書き出します。画像を渡せないAIにも画面の意図が伝わります。

### 4. AIが迷いそうな箇所を先に潰す

出力画面に「出力前のチェック」が出ます。入力内容から自動で見つけます。

- 受け入れ条件が未記入の機能がある
- 優先度が「必須」でない機能を今回作るのか決まっていない
- 参照型の項目があるのに参照先のデータが未定義
- 画面が複数あるのに画面遷移が未定義
- 注釈のない画面がある

埋めなくても、指示書の末尾に**「実装前に確認してほしいこと」**として載るので、AIが勝手に決めてしまうのを防げます。

### 5. 出力

- Markdown をクリップボードにコピー
- `.md` ファイルとしてダウンロード
- 画面ごとに PNG / SVG を書き出し（画像も渡せるAIには併せて添付すると精度が上がります）
- 入力内容を JSON で保存・読み込み（続きから作業できる）

出力には以下を付けるかどうかを選べます。

| 設定 | 内容 |
| --- | --- |
| AIへの役割・進め方の指示 | 「まず不明点を挙げてから実装する」「必須から着手する」等を先頭で宣言する |
| 座標の一覧 | 折りたたみで添付する。細かい位置合わせが必要なときに |
| 指定していないこと | 未入力の重要項目を、裁量に委ねる旨とともに明示する |
| 実装前に確認してほしいこと | 入力内容から自動で質問を組み立てる |

## 使い方

1. https://akira-kataoka.github.io/ai-spec-builder/ を開く
2. 「はじめかた」で雛形を選ぶか、サンプルを読み込む
3. 左のメニューを上から埋める（全部埋める必要はありません）
4. 右上の「指示書を出力」→「Markdownをコピー」
5. AIに貼り付けて、開発を依頼する

入力内容はブラウザの localStorage に自動保存されます。サーバーには何も送信しません（外部通信は Content-Security-Policy で全面的に禁止しています）。

### ローカルで使う

このリポジトリをダウンロードして `index.html` をダブルクリックするだけで動きます。ビルドもサーバーも不要です。

```
git clone https://github.com/akira-kataoka/ai-spec-builder.git
```

### 保存についての注意

- **同じ指示書を複数のタブで開かないでください。** 保存領域が1つなので、あとから閉じたタブの内容で上書きされることがあります（別のタブでの編集を検知すると警告を出します）。
- 「新規作成」と「読み込み」は**1回だけ元に戻せます**（実行直後のトーストから）。
- Safari で `file://` から開くと localStorage が使えず自動保存が効きません。この場合は起動時に警告が出るので、「保存(JSON)」でこまめに書き出してください。

## 画面設計エディタの操作

| 操作 | 方法 |
| --- | --- |
| 部品を置く | 左のパレットをクリック、またはキャンバスへドラッグ |
| 選択 | クリック / Shift+クリックで複数選択 / 空白部分をドラッグで範囲選択 |
| 移動 | ドラッグ、または矢印キー（Shift+矢印で4倍） |
| リサイズ | 選択中に表示される8つのハンドルをドラッグ |
| ラベルを編集 | 部品をダブルクリック |
| コピー / 貼り付け / 切り取り | Ctrl+C / Ctrl+V / Ctrl+X（別の画面にも貼れます） |
| 複製 | Ctrl+D |
| 削除 | Delete |
| 全選択 | Ctrl+A |
| 取り消し / やり直し | Ctrl+Z / Ctrl+Shift+Z（Ctrl+Y も可） |
| 選択解除 | Esc |

複数選択すると、右パネルから**整列**と**等間隔配置**ができます。

部品を選ぶと右側で、表示テキスト・**AIへの注釈**・部品ごとの設定（テーブルの列、リストの項目、ボタンの種類など）・位置とサイズ・遷移先を編集できます。何も選択していないときは、画面名・画面サイズ（PC / タブレット / スマートフォン）・画面全体の説明を編集でき、画面の複製と削除もできます。

スマートフォンなど狭い画面では、パレットとプロパティはツールバーの「部品」「設定」ボタンから引き出しとして開きます。

## ファイル構成

```
index.html            画面の骨格
assets/style.css      スタイル
src/shapes.js         ワイヤーフレーム部品40種のSVG描画定義
src/state.js          指示書データの保持・保存・復元・読み込み時の検証
src/templates.js      雛形4種と記入済みサンプル
src/ui.js             DOM生成・アイコン・フォーム部品・モーダル
src/sections.js       フォーム系10セクションの描画
src/screens.js        画面設計エディタ（SVGキャンバス）
src/markdown.js       Markdown指示書の生成（入れ子構造の組み立てを含む）
src/app.js            起動・ナビゲーション
tests/run-tests.html  回帰テスト（ブラウザで開くと自動実行）
```

外部ライブラリ、CDN、フォントの読み込みは一切ありません。アイコンはすべてSVGで、絵文字は使っていません。

### テスト

`tests/run-tests.html` をブラウザで開くと、136件のテストが自動で走って結果が表示されます。実際のDOMに対してポインタ操作やキー操作を流し込み、エディタの挙動・Markdownの構造・壊れたJSONへの耐性・XSSが起きないことまで確認します。

ヘッドレスでも実行できます。

```
chrome --headless=new --dump-dom tests/run-tests.html
```

### 部品を追加したい場合

`src/shapes.js` に1エントリ足すだけで、パレット・キャンバス・Markdown出力すべてに反映されます。

```js
SB.shapes['mypart'] = {
  name: '部品名', category: '表示', w: 200, h: 60,
  props: [{ key: 'variant', label: '種類', type: 'select', options: [...] }],
  draw: function (n) { return '<rect .../>'; },   // (0,0)起点のSVG文字列
  describe: function (n) { return '部品名「' + n.label + '」'; }  // Markdownに出る説明
};
```

`draw` が返すSVGは PNG に変換されるため、`foreignObject` とCSS変数は使えません。中に他の部品を入れられる部品（カードやモーダルの類）を追加するときは、`src/markdown.js` の `CONTAINER_TYPES` にも追加してください。
